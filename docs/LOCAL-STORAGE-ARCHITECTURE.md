# معماری زیرساخت ذخیره‌سازی محلی و پشتیبان‌گیری

این سند، معماری فنی یک خدمت مشترک زیرساختی را توضیح می‌دهد؛ این قابلیت **مرکز سازمانی مستقل یا صفحه عمومی جداگانه ندارد**. هر مرکز و سامانه، تنظیمات، خروجی و بازیابی فضای داده خود را در همان محیط عملیاتی مدیریت می‌کند.

## ۱. اصل معماری

- هر مرکز، سامانه، معاونت یا شرکت مالک داده تخصصی خود است.
- داده‌های مراکز با شناسه و فضای نام مستقل در موتور مشترک نگهداری می‌شوند.
- موتور ذخیره‌سازی فقط خدمت فنی ثبت، دریافت، فهرست‌گیری، پیوست، ممیزی و پشتیبان‌گیری را ارائه می‌کند.
- هیچ رابط مستقل با عنوان «مرکز داده و محتویات هلدینگ» در درگاه یا منوی مراکز قرار نمی‌گیرد.
- مسئولیت چرخه عمر اسناد، دانش، پروژه‌ها و اطلاعات تخصصی در همان مرکز مالک باقی می‌ماند.

## ۲. اجزای فنی موجود

| جزء | مسیر | مسئولیت |
|---|---|---|
| موتور ذخیره‌سازی محلی | `assets/js/local-data-vault.js` | IndexedDB، فضای نام، رکورد، پیوست و رویداد |
| شناسه‌های سازمانی | `assets/js/organization-registry.js` | شناسه پایدار معاونت‌ها، شرکت‌ها و شعب |
| مرکز مدیریت دانش | `centers/knowledge/` | ذخیره و بازیابی اقلام دانشی در فضای اختصاصی |
| مرکز پروژه‌ها | `centers/projects/` | نگهداری پروژه‌ها، کارها، خط مبنا، برنامه و وقایع در فضای اختصاصی |

## ۳. قواعد فضای داده

هر مرکز باید یک شناسه ثابت و مستقل داشته باشد؛ برای مثال:
- `knowledge-center`
- `project-center`

هر رکورد حداقل باید شناسه یکتا، نوع، قلمرو، نسخه ساختار، زمان ایجاد/به‌روزرسانی و منشأ داشته باشد. نام فایل یا عنوان به‌تنهایی شناسه یکتا نیست.

داده خام، داده تأییدشده و داده مشتق‌شده باید از هم قابل تشخیص باشند. نسخه‌های مصوب و سوابق تغییر نباید بی‌ردپا بازنویسی شوند.

## ۴. پشتیبان‌گیری و بازیابی

- هر مرکز از تنظیمات داخلی خود خروجی پشتیبان JSON نسخه‌بندی‌شده می‌گیرد.
- بازیابی باید با کنترل قالب و نسخه انجام شود و تا حد امکان گزینه ادغام/جایگزینی روشن داشته باشد.
- فایل‌های پشتیبان باید در محل امن خارج از مرورگر نگهداری شوند؛ ذخیره محلی به مجوز و اقدام کاربر وابسته است.
- پشتیبان معتبر باید با آزمون بازیابی دوره‌ای سنجیده شود.
- صفحه وب به‌تنهایی نمی‌تواند خودکار در هر مسیر دلخواه سیستم‌عامل یا GitHub بنویسد.

## ۵. مرز وضعیت فعلی

نسخه فعلی از IndexedDB مرورگر و سازوکار سازگاری localStorage استفاده می‌کند. داده‌ها به همان مرورگر/دستگاه وابسته‌اند مگر اینکه پشتیبان به‌صورت دستی منتقل شود.

موارد زیر هنوز نیازمند زیرساخت سازمانی هستند:
- احراز هویت و کنترل دسترسی نقش‌محور و قلمرو‌محور.
- API و پایگاه‌داده مرکزی.
- همگام‌سازی بین دستگاه‌ها و کاربران.
- صف تبادل و حل تعارض نسخه‌ها.
- رمزنگاری، ممیزی متمرکز، پایش سلامت و پشتیبان‌گیری خارج از دستگاه.
- آزمون خودکار بازیابی و سیاست نگهداری چندنسخه‌ای.

## ۶. قواعد توسعه

1. مرکز جدید نباید موتور ذخیره‌سازی موازی و ناسازگار ایجاد کند.
2. هر مرکز باید scope مستقل و قرارداد داده نسخه‌دار داشته باشد.
3. انتقال داده میان مراکز فقط با ارجاع یا بسته تبادل تعریف‌شده انجام شود؛ کپی بی‌ردپا ممنوع است.
4. داده مرجع نزد سامانه مالک باقی می‌ماند؛ سایر مراکز مصرف‌کننده آن هستند.
5. امکانات محلی نباید به‌عنوان همگام‌سازی یا همکاری چندکاربره معرفی شوند.
