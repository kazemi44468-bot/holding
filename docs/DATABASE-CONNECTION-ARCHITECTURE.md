# معماری مرکز یکپارچه مدیریت دیتابیس هلدینگ

## وضعیت پیاده‌سازی
- رابط مرکزی مدیریت پروفایل اتصال و وضعیت مخزن محلی در `pages/holding-database-center.html`.
- پروفایل‌های غیرمحرمانه اتصال در موتور `HoldingLocalDataVault` و فضای مستقل `holding-db-connections` ذخیره می‌شوند.
- رمز عبور دیتابیس در پروفایل، IndexedDB، localStorage، فایل خروجی یا مخزن GitHub ذخیره نمی‌شود.
- خروجی/ورودی پروفایل فقط مشخصات غیرمحرمانه را منتقل می‌کند؛ اتصال واردشده باید دوباره آزمایش شود.
- رابط آزمون اتصال از قرارداد `POST /api/database/test` استفاده می‌کند و فقط پاسخ `{ ok: true, databaseConnected: true }` را موفق تلقی می‌کند.

## مرز امنیتی ضروری
GitHub Pages و JavaScript مرورگر نباید مستقیماً به MySQL/PostgreSQL وصل شوند و نباید اعتبارنامه دیتابیس را دریافت و نگهداری دائمی کنند. برای اتصال واقعی، یک سرویس API سمت سرور لازم است. آن سرویس باید:
1. فقط روی HTTPS و با احراز هویت مدیر مجاز در دسترس باشد.
2. اعتبارنامه دیتابیس را فقط سمت سرور و در Secret Manager یا متغیر محیطی امن نگهداری کند؛ نه در فایل عمومی یا پاسخ API.
3. ورودی‌ها را اعتبارسنجی کند، محدودیت IP/شبکه و دسترسی حداقلی دیتابیس را اعمال کند و از SQL پارامتری استفاده کند.
4. عملیات تغییر اتصال و چرخش رمز را ممیزی کند.
5. برای اتصال‌ها health check و timeout داشته باشد و جزئیات رمز/خطاهای حساس را در پاسخ به مرورگر برنگرداند.

## قرارداد API پیشنهادی
- `POST /api/database/test`: آزمایش اتصال با اعتبارنامه موقت؛ پاسخ فقط وضعیت و پیام غیرحساس.\n- `POST /api/database/connections/{id}/rotate-secret`: ثبت یا تعویض رمز در مخزن امن سرور؛ پاسخ موفق باید `secretStored: true` داشته باشد. رمز خام نباید در پایگاه داده تنظیمات یا لاگ ذخیره شود؛ Secret Manager یا رمزنگاری کلید-محور سمت سرور لازم است.
- `GET /api/database/connections`: فهرست پروفایل‌های ثبت‌شده سمت سرور، بدون رمز.
- `POST /api/database/connections`: ایجاد پروفایل امن در سرور.
- `PUT /api/database/connections/{id}`: ویرایش پروفایل و جایگزینی رمز در Secret Manager.
- `POST /api/database/connections/{id}/rotate-secret`: تعویض اعتبارنامه با آزمون و امکان rollback.
- `POST /api/sync/preview` و `POST /api/sync/commit`: پیش‌نمایش و اجرای همگام‌سازی نسخه‌دار پس از تأیید مدیر.

## ذخیره‌سازی محلی
موتور عمومی هلدینگ در `assets/js/local-data-vault.js` از IndexedDB استفاده می‌کند. این مخزن در همان مرورگر و دستگاه باقی می‌ماند؛ GitHub Pages اجازه نوشتن مستقیم در پوشه پروژه را نمی‌دهد. برای ذخیره فایل واقعی در پوشه سیستم و استفاده چندصفحه‌ای/چندکاربره باید از سرویس محلی یا برنامه دسکتاپ استفاده شود. مرکز دسکتاپ معاونت ۷ در `deputies/deputy-07/local-data/` نمونه عملیاتی موجود است.

## مهاجرت داده
هر مرکز باید scope ثابت، شناسه پایدار و schemaVersion داشته باشد. مهاجرت به سرور ابتدا در حالت preview انجام می‌شود؛ تعداد درج/به‌روزرسانی/تعارض و checksum گزارش می‌شود و پس از تأیید مدیر commit می‌گردد. هیچ تعارضی نباید بی‌اجازه با آخرین‌نویسنده برنده حل شود.
