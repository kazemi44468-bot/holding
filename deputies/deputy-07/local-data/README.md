# مرکز داده و پشتیبان‌گیری شرکت هفت

این پوشه برنامه مستقل آفلاین و نسخه وب نصب‌پذیر مرکز داده معاونت ۷ را نگهداری می‌کند.

## معماری نسخه اولیه
- رابط وب مستقل و قابل نصب (PWA)، بدون CDN یا سرویس خارجی؛ امکان ثبت رکوردهای JSON و فایل‌های پیوست تا سقف ۲۰ مگابایت برای هر فایل.
- بسته‌بندی دسکتاپ ویندوز با Tauri 2.
- مخزن محلی IndexedDB در نسخه وب و WebView دسکتاپ؛ نسخه دسکتاپ یک snapshot رمزگذاری‌شده را در پوشه AppData نگهداری می‌کند.
- رمزگذاری AES-256-GCM و مشتق‌سازی کلید با PBKDF2-SHA256 و ۳۱۰٬۰۰۰ دور.
- بسته تبادل H7BACKUP رمزگذاری‌شده، شامل رکوردها و پیوست‌ها، قابل انتقال با USB یا پوشه اشتراکی شبکه داخلی.
- دفتر تغییرات، شناسه مستقل رایانه، حذف منطقی و شناسایی شاخه‌های متعارض.

## اجرا در مرورگر
از مسیر انتشار GitHub Pages، پوشه local-data را باز کنید. برای نصب PWA، سایت باید در HTTPS باز شود. سرویس‌ورکر پس از اولین بارگذاری، فایل‌های رابط را برای اجرای آفلاین کش می‌کند.

## ساخت نرم‌افزار ویندوز
نیازمند Node.js، Rust و پیش‌نیازهای ساخت Tauri 2 در ویندوز است:
- npm install
- npm run tauri -- build

خروجی بسته نصب در مسیرهای استاندارد Tauri زیر src-tauri/target/release/bundle تولید می‌شود.

## مسیر داده در نرم‌افزار دسکتاپ
پس از بازگشایی مخزن، مسیر AppData در صفحه نمایش داده می‌شود. فایل جاری با نام vault-state.h7vault، نسخه جایگزین بازیابی و snapshotهای روزانه در همان پوشه و زیرپوشه snapshots نگهداری می‌شوند. بسته‌های دستی در زیرپوشه backups ذخیره می‌شوند؛ برای انتقال با USB، فایل‌های h7backup را از این پوشه کپی کنید.

## انتقال داده از نسخه وب به نرم‌افزار دسکتاپ
۱. نسخه وب را در همان مبدأ GitHub Pages باز کنید و مخزن مرورگر را بازگشایی کنید.
۲. ابزار «انتقال اطلاعات مرورگر» را اجرا کنید تا کلیدهای شناخته‌شده معاونت ۷ وارد مخزن شوند.
۳. یک بسته پشتیبان رمزگذاری‌شده بسازید و فایل h7backup را دریافت کنید.
۴. فایل را به رایانه مقصد منتقل کنید؛ در نرم‌افزار دسکتاپ یک مخزن بسازید/بازگشایی کنید و بسته را وارد کنید.
۵. گذرواژه بسته با گذرواژه مخزن محلی متفاوت است و هنگام واردکردن، گذرواژه بسته درخواست می‌شود.

## نکات امنیتی و عملیاتی
- گذرواژه اصلی را در محل امن و جدا از رایانه‌ها نگهداری کنید؛ بدون آن بازیابی بسته رمزگذاری‌شده ممکن نیست.
- بسته‌های پشتیبان را حداقل در دو رسانه مستقل نگهداری و بازیابی را دوره‌ای آزمایش کنید.
- این نسخه هسته مخزن و تبادل را فراهم می‌کند؛ اتصال همه فرم‌های قدیمی وب به این هسته نیازمند مهاجرت تدریجی ماژول‌های فعلی از localStorage است. تا پایان آن مهاجرت، داده‌های قدیمی را از ابزار انتقال اطلاعات مرورگر وارد کنید.
- در نسخه وب، رمزگذاری مربوط به داده‌هایی است که به این مخزن وارد می‌شوند؛ GitHub Pages به‌تنهایی احراز هویت واقعی یا حفاظت سمت سرور برای محتوای عمومی فراهم نمی‌کند.
- نسخه فعلی یک گذرواژه اصلی برای بازگشایی مخزن دارد؛ نقش‌های مستقل رئیس، مدیر اداره و کارشناس و محدودیت دسترسی رکوردی هنوز پیاده‌سازی نشده‌اند. تا تکمیل آن، فقط در حساب کاربری و رایانه مورد اعتماد استفاده شود.
- فایل نصب امضاشده و آزمون‌شده ویندوز پس از ساخت روی محیط ویندوز تولید خواهد شد.


## اجرای مستقل مرکز کنترل معاونت ۷ روی رایانه
این اجرا از سرویس محلی روی همان رایانه استفاده می‌کند و برای باز شدن رابط به اینترنت یا GitHub Pages وابسته نیست.

### اجرای محلی با مرورگر
۱. Node.js نسخه LTS را روی ویندوز نصب کنید.
۲. فایل `start-control-center-local.bat` را از پوشه اصلی معاونت ۷ اجرا کنید.
۳. در اولین اجرا وابستگی‌های محلی نصب می‌شوند؛ سپس مرورگر روی نشانی `http://127.0.0.1:5174/control-center.html` باز می‌شود.
۴. برای توقف، پنجره فرمان را ببندید.

همچنین می‌توان از پوشه `local-data` دستورهای `npm run dev:control-center` و `npm run build:control-center` را اجرا کرد.

### ساخت نسخه دسکتاپ مستقل
از پوشه `local-data`:
- `npm run tauri:control-center -- dev` برای اجرای برنامه دسکتاپ در حالت توسعه
- `npm run tauri:control-center -- build` برای ساخت بسته نصب ویندوز

پیکربندی Tauri مرکز کنترل جدا از برنامه «مرکز داده و پشتیبان‌گیری» نگهداری می‌شود؛ بنابراین تنظیمات و مسیر اجرای برنامه موجود مرکز داده تغییر نمی‌کند. ساخت فایل نصب نیازمند Node.js، Rust و پیش‌نیازهای Tauri 2 است.

### نکته اجرای مستقیم فایل HTML
باز کردن مستقیم `control-center.html` با دوبارکلیک و نشانی `file://` روش پشتیبانی‌شده‌ای نیست؛ چون صفحه از ماژول‌های JavaScript و مخزن رمزگذاری‌شده استفاده می‌کند. برای اجرای کاملاً محلی از فایل BAT/سرور loopback استفاده کنید یا نسخه دسکتاپ را بسازید.

## پایگاه داده و تبادل آفلاین مأموریت‌های معاونت ۷
صفحات «بانک مأموریت‌ها»، «ایجاد مأموریت»، «گزارش مأموریت‌ها» و «پشتیبان‌گیری و بروزرسانی» از یک لایه واسط مشترک استفاده می‌کنند:
- واسط برنامه‌نویسی: `assets/js/mission-store.js` با نام `MissionStore`.
- موتور ذخیره‌سازی: همان `local-data/assets/engine.js` و همان مخزن رمزگذاری‌شده `company-seven-local-vault`؛ پایگاه داده جداگانه و ناسازگار برای مأموریت‌ها ساخته نمی‌شود.
- گروه داده مأموریت: `mission`؛ شناسه هر رکورد با پیشوند `mission:` نگهداری می‌شود تا با شناسه رکوردهای سایر بخش‌ها تداخل نداشته باشد.
- قالب هر رکورد دارای `schemaVersion: 1`، شناسه پایدار، زمان ایجاد و زمان آخرین ویرایش است. تغییرات در دفتر تغییرات ثبت می‌شوند و حذف، منطقی است.
- بسته تبادل مأموریت از قالب رمزگذاری‌شده H7BACKUP استفاده می‌کند. برای حفظ هماهنگی بین ماژول‌ها، بسته خروجی فعلی کل مخزن مشترک معاونت ۷ را در بر می‌گیرد، نه فقط مأموریت‌ها.
- صفحه مأموریت‌ها به‌صورت PWA قابل نصب است. پس از بارگذاری اولیه و تکمیل کش در حالت آنلاین، فایل‌های صفحات مأموریت و موتور محلی برای اجرای آفلاین در همان مرورگر در دسترس خواهند بود.

### گردش کار بین رایانه‌ها
۱. هر رایانه باید یک‌بار در حالت آنلاین صفحات مأموریت را باز کند تا فایل‌های لازم کش و برنامه نصب‌پذیر شود.
۲. در هر رایانه، مخزن محلی با گذرواژه اصلی یکسان بازگشایی شود؛ داده‌ها در فضای محلی همان مرورگر/برنامه نگهداری می‌شوند.
۳. پس از کار آفلاین، از صفحه «پشتیبان‌گیری و بروزرسانی مأموریت‌ها» بسته رمزگذاری‌شده تهیه شود.
۴. بسته با حافظه USB یا شبکه داخلی به رایانه دیگر منتقل و وارد شود.
۵. تغییرات تکراری دوباره ثبت نمی‌شوند؛ تعارض‌های ویرایش هم‌زمان باید بررسی و تعیین تکلیف شوند. این تبادل در نسخه فعلی خودکار و لحظه‌ای نیست.

### مسیر توسعه به پایگاه داده هاست
صفحات مأموریت باید فقط از `MissionStore` استفاده کنند و مستقیماً به IndexedDB یا موتور رمزگذاری وابسته نشوند. در مرحله اتصال به سرور، پیاده‌سازی همین واسط می‌تواند به API و پایگاه داده مرکزی تغییر کند؛ قالب نسخه‌دار رکوردها و شناسه‌های مأموریت حفظ می‌شوند و برای مهاجرت داده‌ها، تبدیل نسخه (schema migration) اضافه خواهد شد. تا پیش از پیاده‌سازی سرور، همگام‌سازی بین رایانه‌ها به روش بسته‌های رمزگذاری‌شده و انتقال دستی انجام می‌شود.
