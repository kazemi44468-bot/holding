# مرکز مدیریت دانش، تجربه و انتشارات

این پوشه، ریشه محصول عملیاتی مرکز مدیریت دانش است؛ نه صفحه معرفی یا سند طرح.

## ساختار محصول

```text
centers/knowledge/
├── index.html                 # میزکار و نمای کلی
├── pages/
│   ├── repository.html        # مخزن و جست‌وجوی دانش
│   ├── capture.html           # ثبت دانش و تجربه
│   ├── lessons.html           # درس‌آموخته‌ها
│   ├── experts.html           # شبکه خبرگان
│   ├── publishing.html        # تألیف و انتشارات
│   ├── workflow.html          # کارتابل بررسی و تأیید
│   ├── reports.html           # گزارش‌ها
│   └── settings.html          # پشتیبان‌گیری و بازیابی
└── assets/
    ├── css/app.css            # پوسته و طراحی مشترک محصول
    └── js/app.js              # منطق، داده نمونه و گردش‌کار نسخه اولیه
```

## قابلیت‌های نسخه اولیه

- میزکار آماری و دسترسی سریع به بخش‌ها
- ثبت انواع دانش، مستند، تجربه اجرایی، درس‌آموخته و پیشنهاد بهبود
- تعیین واحد، مالک دانش، ثبت‌کننده، کلیدواژه و سطح دسترسی
- مخزن قابل جست‌وجو و فیلتر بر اساس نوع و وضعیت
- کارتابل بررسی با گردش وضعیت و تأیید
- بانک درس‌آموخته‌ها و الگوی تحلیل تجربه
- پرونده شبکه خبرگان و تخصص‌ها
- سبد آثار و مدیریت مرحله تولید و انتشار
- گزارش ترکیب محتوا و مشارکت واحدها و خروجی CSV
- پشتیبان‌گیری و بازیابی JSON

## داده‌های آزمایشی

در اولین اجرای محصول، چند رکورد نمونه برای نمایش گردش کار و شکل داده‌ها ایجاد می‌شود. این داده‌ها صرفاً آزمایشی‌اند و باید پیش از اتصال به پایگاه داده با داده‌های واقعی جایگزین یا پاک‌سازی شوند.

## وضعیت فنی و محدودیت‌ها

- رابط کاربری چندصفحه‌ای و واکنش‌گراست.
- داده‌ها در حال حاضر در `localStorage` مرورگر و با کلید `holding_knowledge_center_v2` نگهداری می‌شوند.
- اطلاعات بین مرورگرها، دستگاه‌ها و کاربران همگام نمی‌شود.
- احراز هویت، نقش و مجوز واقعی، بارگذاری فایل روی سرور، اعلان و API هنوز پیاده‌سازی نشده‌اند.
- سطح دسترسی فعلی فقط به‌صورت مشخصه رکورد ذخیره می‌شود و کنترل امنیتی واقعی ایجاد نمی‌کند.
- برای نسخه پایگاه داده، مدل اولیه شامل `records`، `experts`، `publications` و `tasks` است. شناسه‌های فعلی باید در مهاجرت حفظ یا به شناسه‌های پایگاه داده نگاشت شوند.

## قواعد توسعه

- هر قابلیت مستقل جدید، صفحه یا زیرصفحه روشن داشته باشد؛ منطق مشترک در فایل‌های assets همین محصول نگهداری شود.
- از ساخت یک فایل HTML عظیم یا افزودن همه قابلیت‌ها به صفحه میزکار خودداری شود.
- پوسته بصری، ناوبری و اجزای پایه در صفحات مرکز یکسان بمانند.
- برای مراکز و سامانه‌های بعدی نیز همین الگوی پوشه‌ای و چندصفحه‌ای با نام و assets اختصاصی همان محصول تکرار شود.
